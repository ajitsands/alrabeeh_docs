Offline-First Auto-Sync Architecture (Internet-Droppable Resilience)
Zero Downtime Guarantee
Stage 1: Normal State
Live Dual-Write Synchronization
When internet connectivity is active, all reception check-ins, CPR reads, and payments write simultaneously to local IndexedDB/SQLite and stream via WebSocket/REST to the central cloud MySQL database.
Stage 2: Internet Drop
Isolated Local Buffer Mode
If the clinic's ISP drops, front-office operations continue uninterrupted. The system stores bookings, CPR card demographic reads, and payments locally in AES-256 encrypted storage with an append-only transactional log.
Stage 3: Connection Restored
Automated RabbitMQ Replay
The moment internet reconnects, the sync dispatcher automatically flushes staged records into RabbitMQ message queues. An automated reconciliation daemon resolves any timestamp conflicts with zero data loss.
